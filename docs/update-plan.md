# 萤 · 小部件个性化更新计划

本文档是 Android 桌面小部件个性化功能的目标清单与开发路线，整理自 2026-08-08 的功能脑暴。计划按阶段推进，每个阶段尽量保持可独立发版，避免长期只有一个半成品分支。

## 标记规则

- `- [ ]`：未开始
- `- [ ]（进行中）`：正在开发，尚未完成
- `- [x]`：已完成，并在条目末尾标注完成版本或日期

## 开发顺序原则

1. 先做底座：数据协议、准点刷新、配置面板是后续所有功能的地基，先打通可减少返工。
2. 视觉先行：壁纸贴纸、取色、主题皮肤的用户感知最强，适合作为第一波发版内容。
3. 内容与交互并行：滚动列表、自定义文案、分区点击彼此独立，可拆成两个小版本。
4. 实用增强与双端一致：在 Android 功能稳定后统一补齐 iOS WidgetKit 对等实现。
5. 趣味主题包放最后：不阻塞主线发版，作为彩蛋版本输出。

## 阶段 0：数据协议与刷新底座

后续视觉、内容、交互全部依赖小部件数据层，先把协议、刷新与配置面板打通。

详细计划、验收标准与验证命令见 [docs/phase-0-plan.md](phase-0-plan.md)。

- [x] P0 扩展小部件数据协议：为 `WidgetEvent` 与 `HomeWidgetPreferences` 预留背景图、主题、单位文案、Emoji、进度、精确时间等字段，读取全部使用 `opt*` 兼容旧数据（2026-08-08，v2 协议）
- [x] P0 午夜准点刷新：用 `AlarmManager.setWindow` 在每天 00:00 后的 5 分钟窗口内触发一次小部件更新，避免 30 分钟轮询造成天数显示滞后（2026-08-08）
- [x] P0 应用内配置面板扩展：按「样式 / 内容」重构分区，预览区实时同步新配置；背景与交互等各自功能落地时再显示（2026-08-08）
- [x] P1 配置数据迁移与降级：旧小部件缺少新字段时保持现有显示效果，不强制用户重新配置（2026-08-08）

手工验收：MuMu 模拟器（x86_64 / Android 12）确认旧小部件视觉与现状一致、跨零点 5 分钟窗口内刷新、改系统时间 / 时区后立即刷新，且无需精确闹钟权限（2026-08-08）。

注意事项：

- RemoteViews 只支持有限 View 操作，动画、手势、自定义 View 受限，后续交互方案需要提前规避。
- 数据协议必须向后兼容，新字段一律 `optString` / `optBoolean` / `optLong` 读取并回退默认值。
- 系统对 `updatePeriodMillis` 有最小 30 分钟限制；准点刷新评估 `WorkManager` 一次性任务与精确闹钟权限，注意厂商电池优化和自启动限制。
- 配置写入后调用 `HomeWidget.updateWidget` 或发送刷新广播，确保小部件即时反映新配置。

## 阶段 1：视觉与壁纸个性化

用户感知最强的第一波功能，优先实现透明贴纸、壁纸取色与相册背景图。

详细计划、验收标准与验证命令见 [docs/phase-1-plan.md](phase-1-plan.md)。

- [x] P1 透明贴纸模式：去掉卡片底色，数字与标题浮在壁纸上，用描边或阴影保证可读性（2026-08-08）
- [x] P1 壁纸取色自动配色：应用侧读取 `WallpaperManager` 主色与深色，生成文字对比色后写回小部件配置（2026-08-08）
- [x] P1 相册背景图模式：使用系统 Photo Picker 选图，压缩缓存后写入小部件配置（2026-08-08）
- [x] P1 材质主题：玻璃、拍立得、霓虹、像素、极简五套预设（2026-08-08）
- [x] P1 节日皮肤：圣诞、生日、新年、中秋等按日期自动切换（2026-08-08）
- [ ] P2 深色与动态色跟随：Android 12+ 支持 Material You 动态取色，跟随系统深浅色
- [ ] P2 天气联动背景：可选接入天气源，按晴、雨、雪更换背景或副文案

注意事项：

- 壁纸取色在应用侧完成，小部件只读取计算好的颜色值，避免在 RemoteViews 中做复杂计算。
- 相册图片必须压缩缓存后再提供给小部件，防止大图解码导致内存问题；Android 13+ 用 Photo Picker 可避免存储权限。
- 字体与主题素材优先打包进资源，RemoteViews 不支持运行时下载字体。
- 节日皮肤按本地日期判断，避免时区边界导致提前或延迟切换。

## 阶段 8：预览与桌面渲染一致性

把“该显示什么、用什么颜色字号对齐”收敛为一份由 Flutter 生成的渲染配置，Android 桌面小部件直接消费，避免两端各自推演默认规则导致预览与真实小部件不一致。

- [x] 渲染协议升级 v8：新增 `widget_render_spec`，按 `compact / full` 两个尺寸分支输出全部元素的最终可见性、颜色、字号档位与对齐，并携带事件顺序与空状态文案（2026-08-10）
- [x] Dart 解析器：`resolveWidgetRenderSpec` 统一处理事件排序（置顶优先、距离近优先）、紧凑分支默认值、元素颜色 / 字号 / 对齐与按钮显隐；`WidgetService.sync` 随偏好一起写入（2026-08-10）
- [x] 应用内预览：小号 / 中号预览改由同一解析器驱动，补齐空状态 `-- 天`、添加 / 上 / 下 / 完成按钮，并同步列表模式小号 2 行与副标题显示规则（2026-08-10）
- [x] Android 消费：`DaymarkWidgetProvider` 按真实尺寸选择 `compact / full` 分支应用颜色、字号、对齐与显隐；补齐「上一个 / 下一个」按钮的显隐与配色；spec 缺失时回退旧逻辑（2026-08-10）
- [x] 契约测试：`android/app/src/test/resources/widget_parity` 共享 fixture 同时被 Flutter 与 Android 单元测试校验，覆盖空状态、单事件与列表模式（2026-08-10）

验证：`flutter analyze`、`flutter test`、`gradlew :app:testDebugUnitTest` 与 debug APK 模拟器安装均已通过（2026-08-10）。

注意事项：

## 全局注意事项

- RemoteViews 硬限制：不支持手势、复杂动画与自定义 View；滚动用 `RemoteViewsService`，动画用状态位或短时两帧切换。
- 权限与后台：相册优先走 Photo Picker；准点刷新评估精确闹钟权限，并接受厂商后台限制的现实。
- 图片资源：大图先压缩缓存，路径持久化到 `HomeWidgetPreferences`，避免每次刷新重新解码。
- 兼容性：小部件 JSON 保持版本号，新增字段全部向后兼容，旧数据回退默认值。
- 无障碍：所有按钮保留 `contentDescription`，滑动操作保留按钮替代入口，通过 200% 文字缩放回归。
- 测试：每个阶段完成时运行 `flutter analyze` 与 `flutter test`；小部件逻辑用 Android 单元测试或模拟器截图验证，覆盖深色 / 浅色、大字、小 / 中尺寸。
