# 萤 · 赞助制解锁方案

> 目标：核心功能完全免费，只把不常用的趣味 / 装饰功能作为"赞助解锁"；赞助走爱发电自动发货密钥，采用"密钥验证 + 设备绑定 + 本地解锁"；不走应用商店、不做订阅、不限制核心功能，最大限度保护免费用户与口碑。

> 实施状态：代码已完成并提交（v3.0.0+6）；正式签名 APK 已构建；Cloudflare Worker 部署脚本已就绪，等待 Token 权限补齐后上传。

## 1. 模式定位

- 赞助制不是售卖：所有界面与文案使用"赞助支持"，不用"购买 / 收费 / 订阅"。
- 免费用户无功能损失：不限制事件数量、提醒条数、小部件实例，也不限制数据相关功能。
- 解锁范围只覆盖低频、纯趣味、纯外观的功能，属于"喜欢再支持，不支持也不影响使用"。
- 适合个人开发者：不需要企业资质、不需要商店账号与抽成，渠道成本最低。

## 2. 为什么采用"爱发电自动发货密钥 + Workers 验证"

- 用户在爱发电完成赞助后，平台自动发货一串复杂密钥，用户复制到 App 内验证即可解锁。
- 首次验证成功后解锁状态写入本地；不卸载、不换设备就不需要联网，也不需要二次验证。
- 卸载重装或换设备后，重新输入同一把密钥即可恢复，不需要再次付款。
- 密钥不可猜测且独立编号，Cloudflare Workers 负责验签与设备绑定。
- 爱发电只负责收款与自动发货，不保存用户事件数据；核心数据仍然本地优先。
- 分发走 GitHub Releases 直发 APK，项目已有 GitHub 应用内更新检测，天然配套。

## 3. 功能分层

### 3.1 免费版（保留全部常用功能）

- 事件创建、编辑、删除、搜索、分类、排序、置顶、连续撤销。
- 倒计时 / 正计时、日历总览、每年重复。
- 每事件最多 5 条提醒、通知快捷操作、提醒诊断。
- 深色 / 浅色 / 跟随系统主题。
- 桌面小部件：总览与单事件、基础常用样式（卡片 / 贴纸 / 玻璃 / 极简等）、相册背景、基础颜色与字号、列表模式、快速完成、数据同步。
- 数据导出与导入。

### 3.2 赞助解锁（只解锁不常用功能）

| 功能 | 说明 |
| --- | --- |
| 整活样式 | 神秘信封、时间胶囊、复古 CRT、霓虹灯牌、像素血条、镜像整活 |
| 节日皮肤 | 节日自动换肤 |
| 壁纸取色 | 从壁纸提取小部件配色 |
| 每日一句 | 小部件每日文案 |
| 神秘模式 | 小部件隐藏关键信息 |
| 数字字体 | 数字字体切换 |
| 文字描边 | 文字描边效果 |

> 原则：凡是"很多人会日常用到的"，一律免费；只有"整活、小众、纯外观"的才放进赞助解锁。最终清单由你确认，可随时调整。

### 3.3 赞助档位

- 单档：一次性赞助 ¥5，获得长期赞助解锁，无需订阅。
- 不做多档与订阅，流程保持简单。
- 爱发电页面文案统一写"赞助支持，解锁全部赞助功能"，避免承诺"永久权益"这类强承诺。

## 4. 密钥验证技术方案

### 4.1 密钥生成与自动发货

- 开发者用 `tools/generate_unlock_keys.dart` 批量生成复杂密钥：`YING-` 前缀 + 40 位随机 base62 字符。
- 密钥库存上传到爱发电自动发货；用户赞助后，爱发电自动把其中一把密钥发给用户。
- 每把密钥独立编号；服务端只存 SHA-256 哈希，验证通过后绑定设备，密钥明文不进入用户事件数据。

### 4.2 验证流程

1. 用户在"赞助支持"页打开爱发电主页，完成 ¥5 赞助。
2. 爱发电自动发货，把密钥文本发送给用户。
3. 用户回到 App，粘贴密钥。
4. App 把密钥与设备指纹（Android ID 加盐哈希）发送到 Cloudflare Workers 验证接口。
5. Worker 用 SHA-256 查找密钥哈希，并检查设备绑定关系。
6. 验证通过后，Worker 返回 ECDSA P-256 签名解锁凭证（包含密钥哈希、档位、时间戳、设备哈希、签名），并记录绑定。
7. App 验签成功后写入本地解锁状态；此后断网也能使用。

### 4.3 本地缓存与恢复

- 解锁状态存本地：`sponsor_unlocked`、`sponsor_key_hash`、`sponsor_activated_at`、`sponsor_token`。
- 不卸载、不换设备：启动直接读本地状态，不联网、不二次验证。
- 卸载重装或换设备：本地缓存消失，重新输入同一把密钥即可恢复，不需要再次付款。
- Worker 只负责"验签 + 绑定"，不保存用户事件数据，核心数据仍然本地优先。

### 4.4 防泄漏与设备绑定

- 密钥本身可以分享，但每把密钥最多绑定 2 台设备；第 3 台设备验证时提示"已达绑定上限"。
- 暂不提供转移 / 解绑流程，先按反馈观察；若换机用户频繁被锁，再评估开放受控转移。
- 同一设备卸载重装：本地缓存丢失但设备指纹不变，重新验证同一把密钥自动通过，不占用新的绑定名额。
- 解锁凭证由 Worker 私钥做 ECDSA P-256 签名，App 内嵌对应公钥验签，防止伪造服务端响应。
- 闭源 + APK 加固可以提高逆向成本；但客户端校验始终存在被破解的边界，低客单场景接受。
- 若要收回权益，Worker 可标记密钥失效，在下次换机 / 重装验证时生效。

## 5. 轻量服务端

### 5.1 部署选项（免费额度）

- Cloudflare Workers（已选定）：免费额度约 10 万请求 / 天，绑定关系用 Workers KV 或 D1 存储，个人规模足够。
- Deno Deploy：免费额度包含每月约 100 万请求，适合简单接口。
- Vercel Hobby：Serverless Functions 有免费额度，但海外节点对国内访问不友好。
- 注意：workers.dev 等海外域名在国内访问可能不稳定；如果主要用户在国内且验证失败变多，再切换到腾讯云函数 / 阿里云函数计算的免费额度，或一台轻量服务器。
- 接口只有"查赞助 + 签发 + 绑定"，个人项目很难达到免费额度上限。

### 5.2 爱发电自动发货（已选定）

- 把生成好的密钥库存配置到爱发电自动发货，赞助成功后自动把密钥文本发给用户。
- 密钥库存需提前生成并上传；每发出一把，App 侧由 Worker 验签 / 校验绑定关系，双端以密钥编号对齐。
- 备选正规平台（爱发电不可用时）：面包多等数字商品平台的自动发货，或独角数卡自建 + 支付宝 / 微信官方商户支付。
- 避免使用"易支付"这类聚合接口：多为灰色通道，有资金与合规风险。

## 6. 技术改动清单

### 6.1 新增

```text
lib/
  models/unlock_state.dart              # 解锁状态：unlocked、keyHash、activatedAt、token
  services/unlock_service.dart          # 调用验证接口、验签、持久化、状态读取
  state/unlock_controller.dart          # Riverpod StateNotifier，启动加载并广播状态
  ui/sponsor_page.dart                  # 赞助说明 + 爱发电入口 + 密钥输入 + 状态
  ui/unlock_gate.dart                   # 统一解锁态组件与入口
server/
  verify_worker.js                      # Cloudflare Worker：验签 + 设备绑定
  wrangler.toml                         # Worker 部署配置
  verify_worker.test.js                 # Worker 接口测试
  generate_signing_keys.mjs             # 生成 ECDSA P-256 签名密钥对
tools/
  generate_unlock_keys.dart             # 批量生成密钥库存，私钥不提交
  upload_keys.js                        # 把密钥哈希导入 Worker KV
  update_afdian_reply.js                # 把密钥库存写入爱发电自动随机回复
```

- `pubspec.yaml` 新增签名验签依赖（`pointycastle`）、`crypto`、`http`；爱发电链接沿用复制到剪贴板的交互。

### 6.2 修改

- `lib/services/storage_service.dart`：新增 `sponsor_unlocked`、`sponsor_key_hash`、`sponsor_activated_at`、`sponsor_token` 键。
- `lib/services/widget_service.dart`：同步写入 `widget_sponsor_unlocked`。
- `lib/ui/settings_page.dart`：分类菜单顶部新增"赞助支持"卡片。
- `lib/ui/settings_category_page.dart`：赞助项（整活样式、节日皮肤、壁纸取色等）未解锁时显示锁标记，点击提示赞助。
- Android `DaymarkWidgetProvider.kt`、`DaymarkDetailWidgetProvider.kt` 与 iOS `DaymarkWidget.swift`：读取赞助标记，未解锁时隐藏整活样式。

### 6.3 与买断制方案的区别

- 不限制事件数量、不限制提醒条数、不限制小部件实例。
- 不做数据功能墙，不出现"请升级后继续使用"的核心阻塞。
- 不接应用商店支付，不依赖 Play Billing / StoreKit。
- 密钥由爱发电自动发货，用户不需要找开发者索要，也不需要在 App 外人工核对。

## 7. 实施步骤

### Phase 0：决策（1 天）

1. 确认赞助解锁功能清单与免费 / 赞助边界。
2. 确认 ¥5 档位、爱发电页面链接与文案。
3. 确认密钥长度与是否需要有效期。

### Phase 1：验证底座（2–3 天）

1. 实现 `tools/generate_unlock_keys.dart` 密钥生成工具与库存导出。
2. 实现 `server/verify_worker.js` 验签、设备绑定与签名凭证签发。
3. 实现 `UnlockService` 请求、验签、持久化与 `UnlockController`。
4. 实现赞助页、设置入口、密钥输入与解锁状态展示。
5. 补充 Dart 单元测试与页面 Widget 测试。

### Phase 2：功能锁（2–3 天）

1. 设置页与小部件样式项加锁。
2. `WidgetService` 同步赞助标记，Android / iOS 原生小部件降级。
3. 小部件回归测试。

### Phase 3：闭源、加固与发布（3–4 天）

1. 仓库转私有（或按需保留 README / 文档），不再公开完整源码。
2. 构建启用 Flutter 混淆（`--obfuscate --split-debug-info`）与 Android R8 / ProGuard。
3. v1 暂不接入付费第三方加固：采用 Flutter 混淆 + 图标树摇 + 签名校验；R8 已尝试但受 `integration_test` release 编译兼容限制，后续需要再单独启用。
4. 验证接口启用 HTTPS、TLS 固定与频率限制。
5. 用 `build_sponsor_release.bat` 构建混淆 APK，发布到公开 release 仓库。
6. 用 `tools/publish_release.js` 更新 Worker `/v1/latest` 版本清单。
7. 配置爱发电页面与自动发货密钥库存。

### Phase 4：上线后（持续）

1. 监控验证接口异常与滥用。
2. 修复恢复验证、版本升级相关问题。
3. 监控绑定数量与异常使用；若换机用户频繁反馈被锁，再评估开放受控转移。

## 8. 测试与验收

- Dart 单元测试：解锁凭证验签（有效 / 无效 / 过期 / 伪造）、本地状态持久化、恢复逻辑。

- 加固后验证：混淆 / 加固产物能正常启动、解锁与更新。
- 发布前跑完整 `flutter test` 与现有 Android 单测。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 客户端被反编译 / 修改绕过 | 收入损失 | 闭源 + 混淆 + APK 加固 + 签名凭证；低客单接受剩余风险 |
| 密钥被分享 / 冒用 | 收入损失 | 每把密钥最多绑定 2 台设备，服务端限频与日志 |
| 爱发电接口或规则变化 | 首次验证失败 | 服务端适配层隔离，App 端不受影响 |
| 验证服务不可用 | 无法首次解锁 / 恢复 | 已解锁设备离线可用；首次失败给出明确重试提示 |
| 用户误以为功能被阉割 | 差评、口碑受损 | 文案强调核心功能完全免费，仅趣味功能可选赞助 |
