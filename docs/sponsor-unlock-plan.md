# 萤 · 赞助制解锁方案

> 目标：核心功能完全免费，只把不常用的趣味 / 装饰功能作为"赞助解锁"；赞助走爱发电，采用"爱发电账号一次性验证 + 本地解锁"；不走应用商店、不做订阅、不限制核心功能，最大限度保护免费用户与口碑。

## 1. 模式定位

- 赞助制不是售卖：所有界面与文案使用"赞助支持"，不用"购买 / 收费 / 订阅"。
- 免费用户无功能损失：不限制事件数量、提醒条数、小部件实例，也不限制数据相关功能。
- 解锁范围只覆盖低频、纯趣味、纯外观的功能，属于"喜欢再支持，不支持也不影响使用"。
- 适合个人开发者：不需要企业资质、不需要商店账号与抽成，渠道成本最低。

## 2. 为什么采用"爱发电验证 + 一次性解锁"

- 用户不需要卡密：在 App 内提交爱发电用户 ID，由轻量服务端查询赞助状态，验证成功即解锁。
- 首次验证成功后解锁状态写入本地；不卸载、不换设备就不需要联网，也不需要二次验证。
- 卸载重装或换设备后，重新提交同一个爱发电用户 ID 即可恢复，不依赖用户保管卡密。
- 爱发电开发者凭证只放在轻量服务端，不进入客户端，避免泄露。
- 分发走 GitHub Releases 直发 APK，项目已有 GitHub 应用内更新检测，天然配套。

注意事项：爱发电开放平台提供的是"开发者查询赞助 / 订单"接口，不是标准 OAuth 登录；因此 App 内的"登录验证"实际是用户填写自己的爱发电用户 ID，App 通过你的服务端查询该 ID 是否完成过赞助。

## 3. 功能分层

### 3.1 免费版（保留全部常用功能）

- 事件创建、编辑、删除、搜索、分类、排序、置顶、连续撤销。
- 倒计时 / 正计时、日历总览、每年重复。
- 每事件最多 5 条提醒、通知快捷操作、提醒诊断。
- 深色 / 浅色 / 跟随系统主题。
- 桌面小部件：总览与单事件、基础常用样式（卡片 / 贴纸 / 玻璃 / 极简等）、相册背景、基础颜色与字号、列表模式、快速完成、数据同步。
- 数据导出与导入。

### 3.2 赞助解锁（只解锁不常用功能）

| 功能 | 说明 |
| --- | --- |
| 整活样式 | 神秘信封、时间胶囊、复古 CRT、霓虹灯牌、像素血条、镜像整活 |
| 节日皮肤 | 节日自动换肤 |
| 壁纸取色 | 从壁纸提取小部件配色 |
| 每日一句 | 小部件每日文案 |
| 神秘模式 | 小部件隐藏关键信息 |
| 数字字体 | 数字字体切换 |
| 文字描边 | 文字描边效果 |

> 原则：凡是"很多人会日常用到的"，一律免费；只有"整活、小众、纯外观"的才放进赞助解锁。最终清单由你确认，可随时调整。

### 3.3 赞助档位

- 单档：一次性赞助 ¥3.99，获得长期赞助解锁，无需订阅（按人民币 ¥3.99 写入；如果指的是 $3.99，告诉我再改）。
- 不做多档与订阅，流程保持简单。
- 爱发电页面文案统一写"赞助支持，解锁全部赞助功能"，避免承诺"永久权益"这类强承诺。

## 4. 爱发电验证技术方案

### 4.1 验证流程

1. 用户在"赞助支持"页打开爱发电主页，完成 ¥3.99 赞助。
2. 回到 App，填写自己的爱发电用户 ID（页面内提供查找指引）。
3. App 把爱发电用户 ID 与设备指纹（Android ID 加盐哈希）发送到轻量服务端验证接口。
4. 服务端带爱发电开发者凭证查询赞助状态，确认该用户已完成目标档位赞助，并检查设备绑定关系。
5. 验证通过后，服务端返回签名解锁凭证（包含用户 ID、档位、时间戳、nonce、签名），并记录绑定。
6. App 验签成功后写入本地解锁状态；此后断网也能使用。

### 4.2 本地缓存与恢复

- 解锁状态存本地：`sponsor_unlocked`、`sponsor_user_id`、`sponsor_activated_at`、`sponsor_token`。
- 不卸载、不换设备：启动直接读本地状态，不联网、不二次验证。
- 卸载重装或换设备：本地缓存消失，重新提交同一个爱发电用户 ID 即可恢复，不需要再次付款。
- 服务端只负责"查询 + 签发"，不保存用户事件数据，核心数据仍然本地优先。

### 4.3 防泄漏与设备绑定

- 爱发电用户 ID 本身是公开信息，只凭 ID 验证等于"知道赞助者的 ID 就能解锁"，必须配合设备绑定。
- 首次验证成功时，App 发送加盐哈希后的设备指纹，不传原始设备标识；服务端记录 `user_id -> device_hash` 绑定关系。
- 同一个爱发电 ID 默认只能绑定一台设备：第二台设备验证时提示"已在其他设备解锁"，并提供受控转移流程（例如 30 天可解绑一次），避免正常换机用户被锁死。
- 同一设备卸载重装：本地缓存丢失但设备指纹不变，重新验证同一个 ID 自动通过，不需要再次付款。
- 卡密方案本质同样可分享，但"一次性兑换 + 绑定首台设备"后分享出去也无法在别的设备使用；方式 C 采用同样的绑定规则。
- 解锁凭证由服务端私钥签名（Ed25519 或 JWT），App 内嵌公钥验签，防止伪造服务端响应。
- 闭源 + APK 加固可以提高逆向成本；但客户端校验始终存在被破解的边界，低客单场景接受。
- 若要收回赞助权益，服务端可屏蔽该用户 ID，在下次换机 / 重装验证时生效。

## 5. 轻量服务端

- 第一版建议 Cloudflare Worker（或同类 serverless）：一个 `POST /v1/verify` 接口即可。
- 服务端职责：持有爱发电开发者凭证、查询赞助状态、签发签名凭证、记录与校验设备绑定、频率限制。
- App 端不保存任何服务端密钥，只保存解锁结果。
- 后续若爱发电提供 OAuth 登录，可平滑升级为真登录，不影响 App 端架构。

## 6. 技术改动清单

### 6.1 新增

```text
lib/
  models/unlock_state.dart              # 解锁状态：unlocked、userId、activatedAt、token
  services/unlock_service.dart          # 调用验证接口、验签、持久化、状态读取
  state/unlock_controller.dart          # Riverpod StateNotifier，启动加载并广播状态
  ui/sponsor_page.dart                  # 赞助说明 + 爱发电入口 + 用户 ID 验证 + 状态
  ui/unlock_badge.dart                  # 赞助徽标
server/
  verify_worker.js                      # 轻量验证接口（Cloudflare Worker 示例）
```

- `pubspec.yaml` 新增签名验签依赖（如 `ed25519_edwards` 或等价实现）、HTTP 依赖（如 `http`），可选新增 `url_launcher` 打开爱发电链接。

### 6.2 修改

- `lib/services/storage_service.dart`：新增 `sponsor_unlocked`、`sponsor_user_id`、`sponsor_activated_at`、`sponsor_token` 键。
- `lib/services/widget_service.dart`：同步写入 `widget_sponsor_unlocked`。
- `lib/ui/settings_page.dart`：分类菜单顶部新增"赞助支持"卡片。
- `lib/ui/settings_category_page.dart`：赞助项（整活样式、节日皮肤、壁纸取色等）未解锁时显示锁标记，点击提示赞助。
- Android `DaymarkWidgetProvider.kt`、`DaymarkDetailWidgetProvider.kt` 与 iOS `DaymarkWidget.swift`：读取赞助标记，未解锁时隐藏整活样式。

### 6.3 与买断制方案的区别

- 不限制事件数量、不限制提醒条数、不限制小部件实例。
- 不做数据功能墙，不出现"请升级后继续使用"的核心阻塞。
- 不接应用商店支付，不依赖 Play Billing / StoreKit。
- 不需要卡密生成、发放与验签工具，用户只需要爱发电账号。

## 7. 实施步骤

### Phase 0：决策（1 天）

1. 确认赞助解锁功能清单与免费 / 赞助边界。
2. 确认 ¥3.99 档位、爱发电页面链接与文案。
3. 确认验证服务部署位置（Cloudflare Worker 或自有 VPS）。

### Phase 1：验证底座（2–3 天）

1. 实现 `server/verify_worker.js` 验证接口与签名凭证签发。
2. 实现 `UnlockService` 请求、验签、持久化与 `UnlockController`。
3. 实现赞助页、设置入口、用户 ID 验证与解锁状态展示。
4. 补充 Dart 单元测试与页面 Widget 测试。

### Phase 2：功能锁（2–3 天）

1. 设置页与小部件样式项加锁。
2. `WidgetService` 同步赞助标记，Android / iOS 原生小部件降级。
3. 小部件回归测试。

### Phase 3：闭源、加固与发布（3–4 天）

1. 仓库转私有（或按需保留 README / 文档），不再公开完整源码。
2. 构建启用 Flutter 混淆（`--obfuscate --split-debug-info`）与 Android R8 / ProGuard。
3. APK 接入第三方加固（腾讯乐固、梆梆、爱加密等），并做签名校验。
4. 验证接口启用 HTTPS、TLS 固定与频率限制。
5. 构建并发布 APK 到 GitHub Releases，配置爱发电页面。

### Phase 4：上线后（持续）

1. 监控验证接口异常与滥用。
2. 修复恢复验证、版本升级相关问题。
3. 监控绑定、解绑与转移流程是否被滥用。

## 8. 测试与验收

- Dart 单元测试：解锁凭证验签（有效 / 无效 / 过期 / 伪造）、本地状态持久化、恢复逻辑。
- Flutter Widget 测试：赞助页各状态、加锁项点击行为、验证成功后解锁。
- Android 原生测试：未解锁时整活样式回退。
- 模拟器验证：`adb install` 安装 APK，用测试爱发电用户 ID 验证，重启后状态保持；卸载重装后重新验证可恢复。
- 加固后验证：混淆 / 加固产物能正常启动、解锁与更新。
- 发布前跑完整 `flutter test` 与现有 Android 单测。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 客户端被反编译 / 修改绕过 | 收入损失 | 闭源 + 混淆 + APK 加固 + 签名凭证；低客单接受剩余风险 |
| 爱发电用户 ID 被冒用 / 分享 | 收入损失 | 服务端限频与日志；必要时加设备绑定 |
| 爱发电接口或规则变化 | 首次验证失败 | 服务端适配层隔离，App 端不受影响 |
| 验证服务不可用 | 无法首次解锁 / 恢复 | 已解锁设备离线可用；首次失败给出明确重试提示 |
| 用户误以为功能被阉割 | 差评、口碑受损 | 文案强调核心功能完全免费，仅趣味功能可选赞助 |
